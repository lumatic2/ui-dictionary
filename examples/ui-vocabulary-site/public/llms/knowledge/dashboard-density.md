# Dashboard Density & Low-Noise Hierarchy — 밀도·소음 판정 규칙

Date: 2026-08-01
Milestone: M8 (plan: `plans/2026-08-01-m8-saas-exemplar-absorption.md`)
지위: 대시보드·운영 도구처럼 정보 밀도가 높은 화면의 밀도·위계·소음 판정 정본. 근거 원문은 `research/2026-08-01-m8-dashboard-density-capture.md` 에 동결(Linear 2026-03 리프레시 원문 · Geist Colors) — 이 문서는 판정 규칙만 담는다. 모바일 내비게이션·모달 선택은 [[mobile-navigation]](`knowledge/mobile-navigation.md`) 소관 — 이 문서는 화면 안 밀도·위계만 다루고 컨테이너 선택은 다루지 않는다.

Audience: 에이전트(대시보드·데이터 밀집 화면 생성 시 필수 참조) + 사람.

## 0. 대원칙 — 밀도 ≠ 소음

밀도가 높다는 이유로 정보를 빼지 않는다. 줄이는 것은 **소음**(보더·아이콘 과잉·밝기 경쟁)이고 지키는 것은 **정보 밀도**다. "조밀해서 어수선하다" 진단에 정보 삭제로 답하는 것은 오답이다.

## 1. 주의 예산 (attention budget)

| 요소 | 규칙 |
|---|---|
| 본문 작업 영역 | 화면에서 가장 높은 시각적 우선순위 — 항상 |
| 사이드바·내비 | 도착 후에는 후퇴 — 본문보다 어둡게/저대비로 ("earned attention" — 주의는 얻은 만큼만) |
| 앱 셸 탭·크롬 | 콤팩트하게 — 전폭 점유 대신 축소·라운드, 콘텐츠 밀도는 유지하고 크롬 밀도만 감축 |
| 아이콘 | 엔티티 식별(프로젝트·상태 스캔)에만 — 장식 컬러 배경 금지·개수와 크기 절제 |

## 2. 구조 표현 (structure felt, not seen)

1. **구분의 기본값 = 여백.** 보더·구분선은 이유 없이 증식한다 — 여백 → 배경 미차 → 라운딩 순으로 먼저 시도하고 선은 최후 수단.
2. 선을 쓸 때는 저대비 + 그룹 경계에만(항목마다 긋지 않는다).
3. 페이지 배경은 **2단 상한** — 2단째는 미묘한 구분이 필요할 때만 아껴서 (Geist Background 1/2).

## 3. 상태·위계의 색 규칙

1. **hover/active 는 새 색이 아니다** — 같은 중립 스케일의 인접 단계로 표현한다 (Geist: 배경 1–3 밴드·보더 4–6 밴드). 우리 3-tier 토큰에서는 semantic 단계 인접값 참조로 구현.
2. **텍스트 위계는 2단** — primary/secondary. 세 번째 회색이 필요해 보이면 위계 설계 실패 신호로 읽고 구조를 다시 본다.
3. 저소음 밀집 UI 의 중립색은 저채도로 — 채도는 상태·강조 채널에 아껴 쓴다.

## 판정 절차 (에이전트 의무)

1. 대시보드·밀집 화면을 만들기 전에 §0 을 선언한다 — 정보를 줄일지 소음을 줄일지 구분.
2. 크롬(내비·탭·툴바)과 콘텐츠를 나눠 §1 주의 예산을 배분한다 — 크롬이 콘텐츠와 밝기 경쟁하면 FAIL.
3. 구분선을 넣기 전에 §2-1 순서(여백→배경→라운딩→선)를 거쳤는지 확인한다.
4. hover/active/보더 색이 스케일 밖 새 색이면 §3-1 위반 — 토큰 스케일 인접 단계로 교체.
5. 스타일 수치(Linear 그레이 값·Geist 색 값)는 흡수 대상이 아니다 — look 은 프로젝트 토큰 소유.
