# 완료 — M28 CLI 0.4.1 폴리싱 (킥스타트 handoff + verify 오탐)

> 완료: 2026-08-05 · M28 (goal `cli-polish-041`) · 배치: `docs/reports/` (record — 작성 후 동결)

## 1. 결과

킥스타트가 **인쇄한 안내를 그대로 따라가면 빌드가 된다.** M27에서 신선 빌드를 깨뜨렸던 경로(인쇄된 설치 목록에 cva 누락)를 그대로 다시 밟아 통과했고, 존재하지 않는 심볼(`SaasAppShell`)을 가리키던 render 안내는 블록별 실제 export(`MarketingLandingPage`)로 바뀌었다. dep 은 registry 선언이 아니라 **이식한 파일의 import 에서 실측**하므로 같은 결함이 다음 primitive 에서 재발하지 않는다.

verify 는 더 이상 토큰 준수 코드를 위반으로 부르지 않는다. `[stroke='#ccc']` 같은 속성 셀렉터 안의 hex 는 recharts 내장 기본색을 **겨냥하는 매치 대상**이고 그 줄이 하는 일이 곧 토큰 치환이었다 — 잡히던 게 역전이었다.

오너 관측으로 마케팅 랜딩에서 그라디언트 카드와 미디어 슬롯 테두리가 사라졌고(슬롯에 컴포넌트를 넣으면 프레임이 이중이 된다는 지적), 로고 마키는 중앙 정렬되고 hover 로 멈춘다. `0.4.1` 은 npm 에 있다.

## 2. 이슈와 해결

- **마키 hover 가 안 멈추던 진짜 이유**: `hover:[&>div]:[animation-play-state:paused]` — 쌓인 variant 는 오른쪽에서 왼쪽으로 적용돼 결과 셀렉터가 `.strip > div:hover` 가 된다. `group`/`group-hover` 로 교체.
- **1차 마스킹 구현이 불완전**: 같은-따옴표 JS 문자열 안의 `\"#ccc\"` 형태를 놓쳐 fixture 가 적발. 패턴에 이스케이프 허용 추가.
- **계획 대비 드리프트(확장) 1건 — 정직한 기록**: step-3 Files 는 블록 소스만 적었는데 asset 2종(`logo-marquee`·`zigzag-story-section`)도 고쳤다. 오너 지목(마키 정렬·hover·슬롯 테두리)이 asset 소유 표면이라 이행에 필요했고 결정 A(a)의 "지목분 반영" 범위 안이지만, **파일 범위는 계획서보다 넓었다.** 다음 계획에서 지목 대상이 asset 에 걸칠 수 있으면 Files 에 미리 포함한다.
- **관측 경로의 제약(승계)**: 블록 JSON 의 asset `registryDependencies` 는 라이브 절대 URL 이라 `--registry` 로컬 서빙으로는 asset 변경분이 오지 않는다. 중간 관측은 asset 2파일을 직접 복사해 했고, 라이브 재확인은 배포 후 step-4 에서 별도로 했다.
- **DoD 잔여**: 없음. 단 **`@/` alias 안내 누락**을 실행 중 발견해 0.4.x 큐로 넘겼다(인쇄된 render 안내가 `@/...` 를 쓰라면서 alias 설정은 안내하지 않아, 신선 vite 프로젝트에서 `tsc -b` 6건 실패 — 두 번의 E2E 모두 수기로 메웠다). 사용자 판단 보류로 이번 patch 에 태우지 않음.
