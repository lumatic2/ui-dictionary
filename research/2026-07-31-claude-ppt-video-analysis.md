## 1. 영상의 핵심 주장

1. **클로드 PPT 두 갈래**: "클로드 디자인"(아마 Claude in Chrome/Design 계열 산출) vs **일반 클로드(챗) + 프로젝트**. 일반 클로드를 써야 하는 결정타 = **차트가 이미지가 아니라 PPT 네이티브 차트**로 나온다 — PowerPoint에서 더블클릭 → 엑셀 시트로 숫자 수정 가능.
2. **5단계 워크플로우**:
   | 단계 | 내용 | 타임스탬프 |
   |---|---|---|
   | ① 스타일 선정 | getdesign.md 사이트에서 브랜드 디자인 시스템 프롬프트 복사 (~70개 회사, 미리보기 제공, "design.md" 버튼) | 1:51–2:35 |
   | ② 프롬프트 커스터마이즈 | 폰트(Pretendard, 파일 업로드)·로고(내 것으로 교체)·비율(16:9 고정)·레이아웃 규칙(챕터명/제목/부제목 위치 고정, 본문 하단 밀도) 반영. **프롬프트 자체는 영어 유지** | 2:35–4:03 |
   | ③ 미세 조정 | 테스트 주제로 **1장씩** 생성→피드백 반복. 말로 안 되면 **수정본 PPT 파일을 직접 만들어 비교쌍(네 것=1p, 내 것=2p)으로 업로드**해 "이 페이지처럼 나오게 프롬프트를 고쳐 줘" | 4:03–6:18 |
   | ④ 프로젝트 세팅 | 완성 프롬프트를 Claude 프로젝트 '지침'에 박제, 로고·참고자료는 '지식'에 업로드. 스타일 수만큼 프로젝트 복수 운영 | 6:18–7:12 |
   | ⑤ 제작·리디자인 | (a) 주제만 입력 → PPT 생성, (b) **기존 저품질 PPT/PDF 업로드 → 내 스타일로 리디자인** (NotebookLM PDF 변환 사례). 마무리 손질 장당 ~1분 | 7:12–8:59 |

## 2. 우리 자산과의 대조

| 영상 요소 | 우리 현황 | 판정 |
|---|---|---|
| 네이티브 차트 PPTX | SL3에서 **pptxgenjs 경로로 이미 실증** (7장 전부 AUTO_SHAPE 텍스트 + 네이티브 CHART, python-pptx 구조 검증) | 이미 보유 — 단 SL3 결론은 "PPTX 심화 중단·HTML/PDF 우선". 영상은 **PPTX 실수요(차트 수정)가 강함**을 시사 → 파이프라인 명확화 근거 |
| getdesign.md 디자인 시스템 프롬프트 | 우리 레포 자체가 **DESIGN.md(Stitch 오픈 포맷) 기반** — 같은 계보. 스킬에 브랜드 스타일 프리셋은 dark/light/askewly 3종뿐 | **흡수 후보**: 외부 브랜드 DESIGN.md → slides.json 테마 변환 경로 |
| 1장 반복 미세 조정 | 스킬은 전체 덱 일괄 생성 + lint. "1장 캘리브레이션" 단계 없음 | **흡수 후보**: 방법론에 캘리브레이션 단계(대표 1장 승인 → 전체 전개) 명문화 |
| 비교쌍 파일 피드백 | 없음 (스크린샷 게이트만) | **흡수 후보**: before/after 비교쌍으로 스타일 교정하는 절차 |
| 프로젝트 지침 박제 | 우리의 등가물 = **스킬 + DESIGN.md** (이미 우월: 버전 관리·lint·검증 내장) | 재현만 하고 등가 매핑 기록 |
| 기존 PPT/PDF 리디자인 입력 | 스킬에 없음 (주제→생성만) | **흡수 후보**: PDF/PPTX → md 추출 → slides.json 재생성 리디자인 트랙 |

## 3. 재현 계획 (제안)

1. **재현 랩**: getdesign.md에서 스타일 1개 선택 → 영상 5단계 그대로 Claude(챗 아님, 이 세션/스킬 환경으로 등가 치환) 수행 → 네이티브 차트 PPTX 산출 → PowerPoint 실개봉·차트 더블클릭 수정 확인. 영상 주장 대비 충실도 장부 기록.
2. **갭 판정**: 재현에서 확인된 것 중 §2 흡수 후보 4건(브랜드 DESIGN.md 테마 변환 · 1장 캘리브레이션 · 비교쌍 교정 · 리디자인 입력 트랙)의 채택/보류 결정.
3. **스킬 업그레이드**: 채택분을 presentation-slides-yusung(HTML 트랙)과 PPTX 파이프라인(pptxgenjs 경로 정본화)에 구현.
