# Checkout Flow — 결제·전환 플로우 판정 규칙

Date: 2026-08-01
Milestone: M9 (plan: `plans/2026-08-01-m9-stripe-checkout-absorption.md`)
지위: 결제·체크아웃처럼 전환이 걸린 플로우 표면의 판정 정본. 근거 원문은 `research/2026-08-01-m9-stripe-checkout-capture.md` 에 동결(Stripe Elements·Checkout, 접근 2026-08-01). 확인 모달·다이얼로그 규칙은 [[mobile-navigation]] §3 소관(액션 ≤2·구체 동사) — 이 문서는 플로우 고유 규칙만 담는다. 폼 일반 밀도·위계는 [[dashboard-density]] 소관.

Audience: 에이전트(체크아웃·결제·가입 등 전환 플로우 생성 시 필수 참조) + 사람.

## 0. 대원칙 — 마찰의 본체는 재입력이다

단계 수를 줄이는 것보다 **입력을 없애는 것**이 우선이다. 같은 정보를 두 번 치게 하는 순간이 이탈 지점이고, 단일/다단 레이아웃 선택은 그 다음 문제(기기·태스크 무게로 결정)다.

## 1. 입력 마찰 제거 (우선순위 순)

1. **건너뛰기 경로 먼저** — 원클릭 지불(월렛·저장 결제) 버튼을 수동 폼 **위에** 병렬로 배치하고 "다른 방법으로 결제" 구분선으로 폼과 나눈다. 폼은 폴백이다.
2. **저장·재사용** — 반환 사용자는 지불·배송 정보 자동채움 + 블록별 "변경" 진입점. 새 기기 검증은 일회용 코드로.
3. **자동채움을 막지 않는다** — 브라우저·서드파티·인증 서비스 자동채움 호환은 설계 요건이다(autocomplete 속성·표준 필드 시맨틱).
4. **주소는 자동완성 + 확정 블록** — 타이핑 절감이자 오배송·세금 오적용 방지 검증.
5. 모바일: 숫자 입력엔 동적 숫자 키패드, 카드 스캔 경로 제공.

## 2. 검증·에러 계약

1. **타이핑 중 인라인 검증** — 제출 시 일괄 에러 금지. 에러는 발생 필드 옆, 서술형("무엇을 어떻게")·로컬라이즈.
2. **예측 가능한 실수는 선제 하이라이트** — 이메일 도메인 오타, 카드 브랜드 불일치.
3. **입력 보조 = 신뢰 신호** — 카드 첫 자리로 브랜드 아이콘 표시, 브랜드별 CVC 힌트, 마스킹. 사용자가 "시스템이 내 카드를 안다"고 느끼게.
4. 결제 폼 접근성(ARIA·포커스)은 기본 탑재 전제 — 포커스·키보드 규율 상세는 focus-keyboard 정본(M10) 참조.

## 3. 신뢰 프레이밍

전환 플로우 표면 **안에** 신뢰 신호를 심는다:
- 반품 정책·지원 연락처·약관 링크 (별도 페이지로 쫓아내지 않는다)
- **명세서 표기명 안내** — "결제 내역에 X 로 표기됩니다" (분쟁·챠지백 예방)
- 결제 후 확인 화면에도 같은 표기명 반복.

## 4. 국제화 = 동적 선택

결제수단·통화·언어는 고정 목록이 아니다 — 사용자 위치·선호로 **동적으로 고른다**(로컬 수단 노출이 전환을 올린다는 것이 실측 근거). 가격은 로컬 통화로 표시.

## 5. 플로우 구조 규칙

1. **통합 깊이는 명시적 스펙트럼으로** — hosted 전체 페이지 ↔ embedded 폼(단일/다단) ↔ 컴포저블 요소 ↔ 노코드 링크. 통제 수준과 구축 비용을 트레이드오프로 제시하고 하나를 고른다.
2. **업셀 절제** — cross-sell 은 제안 1개 인라인, 수량 조정 인라인. 업셀이 체크아웃을 별도 페이지로 분기시키면 FAIL.
3. 확인·취소 모달 규칙은 [[mobile-navigation]] §3 을 그대로 따른다.

## 판정 절차 (에이전트 의무)

1. 전환 플로우를 만들기 전에 §0 을 선언 — 이 플로우에서 사용자가 새로 입력해야 하는 필드 수를 세고, 하나씩 "없앨 수 있나(§1)"를 먼저 묻는다.
2. 모든 입력 필드에 §2 검증 계약(인라인·서술형·선제 하이라이트) 적용 여부를 확인한다.
3. 신뢰 신호(§3) 3종 중 최소 2종이 표면 안에 있는지 확인한다.
4. 수치 주장(전환율 %)은 재인용하지 않는다 — 원리만 쓰고 우리 실측으로만 주장한다.
